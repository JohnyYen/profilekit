# Design: Portfolio Data Integration

## Technical Approach

Add a pure-transform generator `generators/generate_portfolio_data.py` mirroring existing
generator patterns (`load_json`, `write_output`, `run`). It reads canonical `data/*.json` and
writes app-consumed JSON into a distinct dir `PORTFOLIO_DATA_DIR = ROOT_DIR/"apps"/"portfolio"/"app"/"data"`.
`generate_all.py` calls it. Three React consumers (`SkillsSection.tsx`, `layout.tsx`,
`CvSection.tsx`) are updated to consume the canonical shapes now emitted. Strict TDD: golden-tested
Python transforms first, then TS consumers, then `pnpm build` verify.

## Architecture Decisions

| Decision | Choice | Rejected | Rationale |
|----------|--------|----------|-----------|
| Generator scope | New standalone script writing to `apps/.../data/` | Extend `generate_portfolio.py` | That script emits `output/portfolio.md`; mixing app-tree writes muddies its contract. Distinct script keeps path scope + golden tests isolated. |
| Skills shape | Passthrough canonical `{categories:[...]}`; update TS to consume it | Lossy bucket map (backend/db/…) | Proposal mandates canonical categories + icon rendering; buckets drop icons and categories. |
| Projects fallback | Map canonical `projects.json` → app `{name,description,tech,url}` | Emit full `Project` shape | `api/github/route.ts` fallback reads only those 4 fields and derives the rest; extra fields harmless but unnecessary. |
| CV size/date | Single documented constants in `CvSection.tsx` | Fabricate from data / add to canonical | Not in canonical `data/`; proposal forbids fabrication. Keep as named constants with a comment. |
| about.json emit | Subset of canonical fields the app imports | Full passthrough | App `AboutData` needs 6 fields; emit exactly those to keep the committed artifact minimal + stable. |
| App data status | Generated-but-committed (like `output/`) | gitignore | Next build imports JSON at compile; must be present in tree. Regenerated by `generate_all`. |

## Data Flow

    data/*.json ──▶ generate_portfolio_data.py (pure transforms) ──▶ apps/portfolio/app/data/*.json
                                                                         │ (static import)
                    SkillsSection / AboutSection / layout / CvSection ◀──┘
    projects: GitHub API (primary) ──▶ api/github/route.ts ──▶ Project[]  (fallback ▶ projects.json)

## Output Shapes (exact)

- **about.json**: `{username, tagline, description, currentFocus, whatIBuild, learningJourney}` — copied from canonical `about.json` (same keys already consumed by `AboutSection`/`terminal.tsx`). Canonical `description` is longer than the current app copy; that is acceptable (single source).
- **social.json**: full passthrough of canonical `social.json` (`github, linkedin, email, cvUrl`) — already identical.
- **skills.json**: passthrough of canonical `{categories:[{label, details}]}` where `details` items are `string | {name, icon?, iconUrl?}`.
- **projects.json**: array; each canonical project mapped to `{name, description, tech, url}` (drop `start_date/end_date/highlights`). Preserve source order. `tech`/`url` default to `""` when absent.

## File Changes

| File | Action | Description |
|------|--------|-------------|
| `generators/generate_portfolio_data.py` | Create | Pure fns `build_about`, `build_social`, `build_skills`, `build_projects` + `main()` under `run`; writes 4 files via `write_output` to `PORTFOLIO_DATA_DIR`. |
| `generators/generate_all.py` | Modify | `import ... as portfolio_data`; call `portfolio_data.main()`; list the 4 app-data paths in the summary. |
| `apps/portfolio/app/data/{about,social,skills,projects}.json` | Modify (generated) | Overwritten by the generator; committed. |
| `apps/portfolio/app/components/tui/sections/SkillsSection.tsx` | Modify | New `SkillsData = {categories:{label,details:(string\|{name,icon?,iconUrl?})[]}[]}`; render icon (skillicons slug via `<img src="https://skillicons.dev/icons?i={icon}">` else `iconUrl`) when present, else text label. |
| `apps/portfolio/app/layout.tsx` | Modify | Import `about.json`/`social.json`; derive `title`, `description`, JSON-LD `name`/`url`/`sameAs`, `authors`/`creator` from data (keep `siteUrl` constant). |
| `apps/portfolio/app/components/tui/sections/CvSection.tsx` | Modify | Card title from `about.username`; `CV_SIZE`/`CV_DATE` named constants (documented). |
| `tests/test_generate_portfolio_data.py` | Create | RED unit tests per builder. |
| `tests/fixtures/portfolio_data/*` | Create | Golden inputs/outputs. |

`terminal.tsx` imports need no change (same paths; TS type flows from the new JSON shape via `resolveJsonModule`). `AboutSection`/`ContactSection`/`SkillsSection` receive typed props — only `SkillsSection` type changes.

## Interfaces / Contracts

```python
# generate_portfolio_data.py
def build_about(about: dict) -> dict          # 6-key subset
def build_social(social: dict) -> dict         # passthrough
def build_skills(skills: dict) -> dict         # {"categories": [...]}
def build_projects(projects: list) -> list     # [{name,description,tech,url}]
```

```ts
// SkillsSection.tsx
type SkillDetail = string | { name: string; icon?: string; iconUrl?: string };
interface SkillsData { categories: { label: string; details: SkillDetail[] }[]; }
```

## Testing Strategy

| Layer | What | Approach |
|-------|------|----------|
| Unit (RED) | Each builder output shape; skills passthrough; projects fallback mapping; about subset; missing `tech`/`url` → `""` | pytest with inline fixtures + golden JSON compare; monkeypatch dirs like `validate.py` |
| Integration | `generate_all` runs new step, writes 4 files | Extend `tests/test_generate_all.py` |
| TS/build | Type + build correctness | `pnpm --dir apps/portfolio install` then `pnpm --dir apps/portfolio build` (or `tsc --noEmit`/eslint); note deps may need install first |

Runner: `uv run pytest -q` (coverage ≥ 80, per config).

## Threat Matrix

N/A for routing/shell/subprocess/VCS-PR/executable classification. One relevant boundary: the
generator writes OUTSIDE `output/` into the app tree. Mitigation is design-level: a single fixed
`PORTFOLIO_DATA_DIR` constant (no user/dynamic path input), `write_output` `mkdir(parents=True)`,
and golden tests asserting exact output paths + content. RED test: builders never traverse outside
`PORTFOLIO_DATA_DIR`.

## Migration / Rollout

No data migration. `apps/portfolio/app/data/*.json` becomes a committed generated artifact;
first `generate_all` run overwrites the hand-maintained copies. Rollback = git checkout of the
generator, wiring, TS files, and app data (no canonical/schema change).

## Sequencing

1. RED tests + golden fixtures for `generate_portfolio_data.py`.
2. Implement generator (GREEN); wire into `generate_all`.
3. Run generator to regenerate committed app data.
4. Update `SkillsSection.tsx` (+type), `layout.tsx`, `CvSection.tsx`.
5. Verify `pnpm build`/typecheck/eslint (install deps first if absent).
